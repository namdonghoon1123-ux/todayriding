# 구현 순서 지침

아래 순서대로 진행한다.

## 1. 프로젝트 상태 확인

작업:

- 현재 저장소 구조를 확인한다.
- 이미 Xcode 프로젝트가 있으면 구조를 분석하고 이어서 작업한다.
- 프로젝트가 없으면 SwiftUI iOS 앱 기준으로 필요한 파일 구조와 코드 초안을 생성한다.

검증:

- 기존 파일과 새로 만들 파일의 경계를 설명할 수 있다.

## 2. 프로젝트 구조 생성

작업:

- Models, Services, ViewModels, Views, Utilities 폴더를 만든다.

검증:

- 앱의 주요 책임이 폴더별로 나뉘어 있다.

## 3. 모델 정의

작업:

- Ride
- RidePoint
- WeatherSnapshot
- AirQualitySnapshot
- RideSummary

검증:

- 홈, 기록, 요약, 공유 카드에 필요한 데이터가 모델로 표현된다.

## 4. Mock 서비스 생성

작업:

- WeatherService 프로토콜
- MockWeatherService
- AirQualityService 프로토콜
- MockAirQualityService

검증:

- API 키 없이 HomeViewModel이 날씨/미세먼지 데이터를 받을 수 있다.

## 5. RidingScoreCalculator 구현

작업:

- 단순 규칙 기반 점수 계산을 구현한다.

검증:

- 강수확률, PM2.5, 풍속, 고온, 고습, 일몰 조건에 따라 점수가 달라진다.

## 6. HomeView 구현

작업:

- 오늘탈까 홈 화면을 만든다.
- 라이딩 시작 버튼을 연결한다.

검증:

- Mock 데이터로 점수와 판단 메시지가 표시된다.

## 7. LocationManager 구현

작업:

- 위치 권한 요청 구조를 만든다.
- CoreLocation 위치 업데이트 구조를 만든다.

검증:

- 위치 권한 요청을 호출할 수 있다.
- 시뮬레이터 또는 Mock 위치로 흐름을 확인할 수 있다.

## 8. RideTracker 구현

작업:

- 라이딩 시작, 일시정지, 재개, 종료 상태를 관리한다.
- GPS 포인트를 누적한다.
- 거리, 시간, 현재 속도, 평균 속도를 계산한다.

검증:

- 위치 포인트가 들어오면 거리/시간/속도 값이 갱신된다.

## 9. RideTrackingView 구현

작업:

- 지도, 경로, 주요 수치, 컨트롤을 표시한다.

검증:

- 라이딩 시작 후 기록 화면으로 이동한다.
- 종료 버튼으로 요약 화면으로 이동할 수 있다.

## 10. 로컬 임시 저장 구현

작업:

- LocalRideStore 프로토콜을 만든다.
- 라이딩 중 포인트를 로컬에 먼저 저장한다.
- pending 상태를 표현한다.

검증:

- 네트워크 없이도 라이딩 데이터가 로컬에 남는 구조다.

## 11. RideSummaryView 구현

작업:

- 라이딩 결과 요약을 표시한다.
- 메모 입력을 제공한다.

검증:

- 거리/시간/평속/최고속도/날씨/미세먼지 정보가 표시된다.

## 12. SupabaseService 초안 구현

작업:

- Supabase 저장 서비스 인터페이스를 만든다.
- 필요한 경우 `/supabase/schema.sql` 초안을 만든다.

검증:

- 실제 키 없이도 컴파일 가능한 인터페이스 또는 Mock 구현이 있다.

## 13. RideSyncService 구현

작업:

- 종료된 라이딩을 Supabase에 동기화하는 흐름을 만든다.
- 실패 시 pending 상태로 남긴다.
- 앱 재실행 시 재시도할 수 있는 구조를 둔다.

검증:

- 업로드 실패가 데이터 유실로 이어지지 않는다.

## 14. ShareCardView / ShareCardRenderer 구현

작업:

- 공유 카드 미리보기를 만든다.
- 이미지 생성/공유 구조를 만든다.

검증:

- 공유 카드 미리보기를 볼 수 있다.
- 자동 업로드 없이 iOS 공유 기능으로 연결할 수 있다.

## 15. 기본 테스트/프리뷰 데이터 추가

작업:

- SwiftUI Preview용 샘플 데이터를 만든다.
- 계산 로직 테스트를 추가한다.

검증:

- 핵심 계산과 화면 프리뷰가 Mock 데이터로 동작한다.

## 16. TODO 목록 정리

작업:

- 알림, HealthKit, GPX, 자동 업로드, 코스 추천 등 제외 기능을 TODO로 분리한다.

검증:

- 1차 MVP 범위와 2차 기능이 섞이지 않는다.
